Compose refuses to start while any required variable is empty. `pilot:preflight` fails on
development defaults, `CHANGE_IN_PRODUCTION*` placeholders, or an empty Redis password (WARN).

## 4. Deployment Steps
Follow `docs/runbooks/DEPLOYMENT.md` §3. Summary: checkout tag → `$DC config` → build → datastores →
`minio-init` → `db-roles` → migrate and seed as `campus_migration_user` → caches → `up -d` →
**initial verified backup** → `pilot:preflight --require-backup` → `scripts/pilot-host-preflight.sh`.

## 4b. First Administrator, Site/Gate and Operator Roles
```bash
$DC exec backend php artisan access:bootstrap-admin <admin-username>          # one-time password printed once
$DC exec backend php artisan locations:provision <SITE_CODE> "<Site name>" --zone="GATE-1:Main Gate:GATE"
$DC exec backend php artisan access:assign-role <username> <ROLE_CODE> --site=<SITE_CODE>   # repeat per operator
```
Role facts for the pilot roster: only DISCIPLINE_OFFICER (and the wildcard admin roles) hold
`event.review`. SECURITY_OFFICER can monitor and view events but can't review them, and can't open the
dashboard API (it requires `report.view`; see V1 audit A-14).

## 5. Storage Volumes

| Volume | Purpose | Backed up by |
|---|---|---|
| `postgres-data` | database | `backup:run --type=POSTGRESQL` (10 min) |
| `minio-data` | object storage (4 buckets) | `backup:run --type=STORAGE` (hourly) |
| `redis-data` | sessions, queue, cache (AOF) | not backed up (transient) |
| `backend-storage` | Laravel storage incl. local backups `storage/app/backups` | the local backups are themselves copied off-host |
| off-host bind (`/var/backups/offhost`) | verified backup copies + `.sha256` | target-side retention |

## 6. Monitoring Endpoints

| Endpoint | Use |
|---|---|
| `https://<host>/healthz` | gateway liveness (nginx only) |
| `https://<host>/health/full` | backend readiness: 200 all OK, 503 if any dependency is down. **External probe target** |
| `/health`, `/health/database`, `/health/redis`, `/health/storage`, `/health/ai` | per-dependency JSON |
| `/system/health` (UI, SYSTEM_ADMIN) | alerts and incidents dashboard |
| automatic alerts | `AI_NODE_DOWN` (CRITICAL), `CAMERA_DOWN` (WARNING, > 120 s), `REDIS_HEALTH`/`STORAGE_HEALTH`/`AI_SERVICE_HEALTH` (CRITICAL), `QUEUE_BACKLOG` (WARNING), `BACKUP_FAILED` (CRITICAL). A PostgreSQL outage can't be stored as an alert: the external probe must catch it |

## 8. AI Node Registration (site team, PENDING hardware)
1. SYSTEM_ADMIN → `/ai-nodes/create`: node code, name, site, hardware type, max cameras = 2.
2. Open the node → **Credentials** → issue a token. Copy it **once** into the node's configuration; never store it elsewhere.
3. Configure the node with the backend URL `https://<host>` (the machine API is `/internal/v1/...` through the gateway).
4. Start the node → within 90 s the status is ONLINE on `/ai-nodes/:uuid`. Stopping it must raise `AI_NODE_DOWN`.

## 9. Camera Registration (site team, PENDING hardware)
1. `/cameras/create` for each of the 2 cameras: code, name, site/zone (gate), RTSP URL + credentials (stored encrypted), assign the AI node.
2. **Test connection** and **Snapshot** from the camera page.
3. Set the ROI to the gate walkway (`/cameras/:uuid` → ROI).
4. Confirm the camera reports health (ONLINE); stopping the stream must raise `CAMERA_DOWN` after 120 s.
5. Never put RTSP URLs with credentials in documents or tickets.

## 11. Rollback Commands
See `docs/runbooks/ROLLBACK.md`. First deployment: `$DC down` (volumes kept) and revert to the manual
gate procedure. Upgrade: retag `smart-campus/*:pilot-previous` → `:pilot`, `$DC up -d --force-recreate`,
restore the verified pre-deployment backup into a **new** database if the data is damaged.
