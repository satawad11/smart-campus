# License Model (COM-02)

**Status:** Implemented in the campus instance (development branch, tested). Commercial terms (plans, prices) are
**not** defined here; see [PRICING_ASSUMPTIONS](PRICING_ASSUMPTIONS.md). Production signing key: **not yet generated**
(human step, §6).

## 1. Principles

| Principle | How it is met |
|---|---|
| Works offline | Verification uses only Ed25519 public keys shipped in `apps/backend/config/license.php`; no call home |
| Private key never in the product | Signing happens in `tools/license-issuer/issue.php` on the vendor's offline workstation; the tool refuses key paths inside the repository; `*.secret` and `*.lic` are git-ignored |
| Tamper-evident | The exact signed text is stored and **re-verified on every evaluation**; editing database columns grants nothing (tested) |
| Never holds data hostage | Enforcement refuses *growth* only. Nothing is ever deleted; viewing, review, reports, **exports**, audit, health, monitoring and existing recognition keep working whatever the license state (tested) |
| Safe default for the approved pilot | `LICENSE_ENFORCEMENT=warn` by default: state is reported and logged, nothing is blocked, no new alerts without a license |

## 2. Signed document format

```json
{"format":"smart-campus-signed/v1","key_id":"vendor-2026-a","payload":"<base64url>","signature":"<base64url>"}
```

The Ed25519 signature covers the exact decoded payload bytes (no JSON canonicalisation). `payload.type` is
`license` or `revocation_list`, so one can never be accepted as the other.

### License payload

| Field | Type | Notes |
|---|---|---|
| `type`, `format_version` | `"license"`, `1` | set by the issuer |
| `license_id` | UUID | generated by the issuer |
| `installation_id` | UUID | from `php artisan license:status` on the customer instance; binds the license to it |
| `licensee.name` | string | customer institution |
| `edition`, `plan` | UPPER_CASE codes | e.g. `COMMERCIAL` / `STANDARD` (plan catalogue: business decision) |
| `features` | list of lower-case codes | today `face` gates new face enrollments; other codes are informational |
| `limits.max_cameras`, `limits.max_ai_nodes` | int ≥ 0 or null | count of **ACTIVE** cameras / AI nodes; null = unlimited |
| `issued_at`, `not_before`, `expires_at` | ISO 8601 | |
| `grace_days` | 0–90 | growth still allowed after expiry for this many days |

### Revocation list payload
`{"type":"revocation_list","format_version":1,"sequence":N,"issued_at":"…","revoked_license_ids":["…"]}` —
`sequence` must increase with every list (an older list can't be replayed); revocations are permanent.

## 3. States

| State | Meaning | Growth allowed |
|---|---|---|
| `NONE` | no license installed | no |
| `NOT_YET_VALID` | before `not_before` | no |
| `VALID` | in term | yes |
| `EXPIRING` | within `LICENSE_EXPIRY_WARNING_DAYS` (30) of expiry | yes |
| `GRACE` | expired, within `grace_days` | yes |
| `EXPIRED` | past grace | no |
| `REVOKED` | on an imported revocation list | no |
| `INVALID` | signature/key/installation check fails on re-verification | no |

**Clock rollback:** expiry is evaluated against max(now, last validation time). `license:check` (hourly) advances the
high-water mark; a clock more than 24 h behind it raises `LICENSE_CLOCK_ROLLBACK` and can't extend a license.

## 4. Enforcement (`LICENSE_ENFORCEMENT`)

| Mode | Behaviour |
|---|---|
| `off` | state reported only |
| `warn` (default) | also logged; `license:check` alerts on expiring/grace/expired/invalid/over-limit (not on a missing license) |
| `enforce` | refuses with HTTP 409: creating or re-activating a camera or AI node beyond the limit or without a usable license; new face enrollment without the `face` feature. Each refusal is audited (`LICENSE_ENFORCEMENT_BLOCKED`). `pilot:preflight` FAILs without a usable license |

An unknown mode value falls back to `warn`. Two simultaneous additions can overshoot a limit by one; the hourly check
then raises `LICENSE_LIMIT_EXCEEDED`.

## 5. Operations

| Task | Command / API |
|---|---|
| Get the installation ID for a quote | `php artisan license:status` or `GET /api/v1/system/license` |
| Install / renew | `php artisan license:install /path/customer.lic` or `POST /api/v1/system/license` (`system.manage`) |
| Import revocations | `php artisan license:import-revocations /path/revocations.lic` or `POST /api/v1/system/license/revocations` |
| Alerts | scheduled `license:check` (hourly): `LICENSE_EXPIRING`, `LICENSE_GRACE_PERIOD`, `LICENSE_EXPIRED`, `LICENSE_INVALID`, `LICENSE_MISSING` (enforce only), `LICENSE_LIMIT_EXCEEDED`, `LICENSE_CLOCK_ROLLBACK` |
| Audit | `LICENSE_INSTALLED`, `LICENSE_REJECTED`, `LICENSE_REVOCATIONS_IMPORTED`, `LICENSE_ENFORCEMENT_BLOCKED` |

Renewal: issue a new license with a later `issued_at`; installing it supersedes the old one (kept as history).
Installing an **older** license over a newer one is refused (`LICENSE_OLDER_THAN_ACTIVE`).

## 6. Vendor key management (human steps — not done)

1. On an offline workstation: `php tools/license-issuer/issue.php keygen --key-id=vendor-YYYY-a --out=/secure/vendor-YYYY-a.secret`.
2. Keep two encrypted offline copies of the secret key (e.g. hardware token / encrypted USB in separate safes). Record custodians.
3. Add the printed **public** key to `$vendorKeys` in `apps/backend/config/license.php` through a reviewed commit; release.
4. Rotation: generate a new key id, ship it alongside the old one, re-issue licenses, then remove the old key in a later
   release. Compromise: ship a release without the compromised key and re-issue every license.
5. Outside production, `LICENSE_TRUSTED_KEYS="kid:base64;…"` may add rehearsal keys; it is ignored when `APP_ENV=production`.

## 7. Known limitations

- A customer with root access to their own server can modify the software; the license deters casual misuse and
  provides audit evidence, it isn't DRM.
- A full database restore onto a cloned server carries the same installation identity (by design: DR must keep
  working). Cloning is a contractual matter.
- Feature entitlements gate only new face enrollments today. Runtime features follow the system feature flags; a
  license can never enable a V1-locked module (door, visitor, vehicle, ALPR, AI assistant).
- No UI yet for license status/installation (API + CLI only) — backlog COM-02c.
