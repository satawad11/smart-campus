# S3-compatible object storage: SeaweedFS (FND-008)

Object storage runs as the `objectstore` service in `docker-compose.yml`:
SeaweedFS (Apache-2.0) with its S3 gateway on `:8333`, pinned by digest. It
replaced MinIO in 2026-11, when MinIO stopped publishing container images.

| File | Purpose |
|---|---|
| [`buckets.txt`](./buckets.txt) | the approved buckets (one per line) |
| [`start.sh`](./start.sh) | container entrypoint: writes the S3 identities from the environment, starts `weed server -s3` |
| [`init.sh`](./init.sh) | one-shot `objectstore-init`: creates the buckets (idempotent) |
| [`migrate-from-minio.sh`](./migrate-from-minio.sh) | one-off `storage-migrate` (rclone): copies a legacy MinIO store, verifies byte for byte, never deletes |

## Identities

- **root** (`OBJECTSTORE_ROOT_USER` / `OBJECTSTORE_ROOT_PASSWORD`): admin.
  Used only by `objectstore-init` and `storage-migrate`, never by the app.
- **app** (the backend's `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`):
  Read/Write/List/Tagging on the buckets in `buckets.txt` only. It cannot
  create buckets, act as admin, or set an object ACL.
- No anonymous identity: unauthenticated requests are refused.

Object ACLs are deliberately not granted: on SeaweedFS a `public-read` object
ACL is served to anonymous clients. The backend therefore never sends one
(`AppServiceProvider` strips `ACL` from uploads and copies), and
`scripts/verify-storage.sh` checks that the app identity cannot set one.

Development defaults live in `docker-compose.yml` / `.env.example`
(`campus-root` / `campus-dev-root-secret`, `campus-dev-app` /
`campus-dev-app-secret`); `pilot:preflight` fails on them. Production values
are generated by the installer.

## Buckets

- `person-photos`
- `face-samples`
- `event-snapshots`
- `report-exports`

Face samples and biometric data are Highly Sensitive (PROJECT_RULES.md §10):
buckets are private; access goes through authorization / signed URLs, never a
public bucket.

## Development

```bash
docker compose up -d objectstore
docker compose run --rm objectstore-init
bash scripts/verify-storage.sh      # static + live least-privilege check
```

## Laravel wiring

`config/filesystems.php` defines one S3 disk per bucket (`person_photos`,
`face_samples`, `event_snapshots`, `report_exports`) plus the generic `s3`
disk, all pointing at `AWS_ENDPOINT` (`http://objectstore:8333`) with
path-style addressing. Bucket names can be overridden with `S3_BUCKET_*`.

## Moving from MinIO (installations before 2026-11)

`deploy/campus-server/install.sh` does this automatically during an update
when the volume `smart-campus_minio-data` exists. It starts the old MinIO,
runs `storage-migrate`, and switches `AWS_ENDPOINT` only after every object
has been verified. The old volume is kept; delete it by hand once you are
satisfied. If the copy fails, the update stops with the app still pointing
at MinIO, so `smart-campus rollback` finds every file.
